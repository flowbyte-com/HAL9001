# HAL9001 Architecture

Implementation notes for the HAL9001 persona in the DeepClaw runtime.
Status: initial milestone implemented; default behavior unchanged when the
persona is off.

## Stage A investigation (seams)

- **Identity** is built in `pkg/agent/context.go` (`getIdentity`,
  `BuildSystemPromptParts`); per-turn assembly flows through
  `buildSystemPromptForRequest` gated by `SuppressToolUseRule`.
- **Tool registration vs visibility** are separate: `pkg/tools/registry.go`
  (`Register`, `SetVisibleTools`, `RegisterProfileTool`) lets a profile
  narrow provider-visible tools without uninstalling anything.
- **Coding-profile gating** (`pkg/agent/coding_profile.go`,
  `applyCodingProfile`/`enableCodingProfile`) is the pattern to mirror:
  applied late in `NewAgentLoop`, after all shared-tool registration.
- **Routing** picks models, never personas; no model-based intent routing
  was added (token-efficiency constraint).
- **MPM** has an in-tree retrieval path (`mpm.Retriever`) but no in-tree
  write path — memory writes are out of scope (see memory contract).
- **Sessions/compaction** are persona-agnostic; nothing there changed.

## Selection

`agents.defaults.persona` (`PICOCLAW_AGENTS_DEFAULTS_PERSONA`):
`"hal9001"` enables the persona (case/whitespace-insensitive);
anything else keeps default behavior. Implemented in
`pkg/agent/hal9001.go` (`Hal9001Enabled`), threaded through
`AgentDefaults.Persona` → `AgentInstance.Hal9001` →
`ContextBuilder.WithPersona`.

## Prompt changes (HAL only)

- Identity block replaced by `Hal9001Identity` (chat-first rules).
- The `ALWAYS use tools` rule is suppressed twice: at the builder level
  (`BuildSystemPromptParts` skips `IncludeToolUseRule`) and per turn
  (`prompt_turn.go` sets `SuppressToolUseRule`).
- No other prompt layers change: workspace bootstrap, skills, memory, and
  runtime context are identical.

## Tool profile (HAL only)

- Registered in `NewAgentInstance`: `draft_prompt`, `review_prompt`
  (`pkg/tools/prompt_workshop.go`, thin adapters over `pkg/promptwork`).
- Visibility applied late in `NewAgentLoop` (`enableHal9001Profile`),
  after shared-tool registration: `web_search`, `web_fetch`,
  `read_file`, `find_skills`, `draft_prompt`, `review_prompt`.
- Coding profile takes precedence: when `DEEPCLAW_CODING_PROFILE=1`, the
  HAL profile is skipped entirely.
- Visibility never widens access: only already-registered,
  config-enabled tools become visible.

## Dave Protocol enforcement

`IsSafetyRefusal` (`pkg/agent/hal9001.go`) recognizes only explicit
provider signals: a narrow normalized finish-reason list
(`contentfilter`, `contentfiltered`, `safety`, `responsibleaipolicy`,
separator-insensitive) and provider safety error substrings. Unknown
signals return false.

Two interception points, both HAL-gated, both requiring empty content:

1. `Pipeline.Finalize` — response-based refusal (empty content, no tool
   calls, safety finish reason): substitutes the exact line, overriding
   the normal fallback.
2. `turn_coord.go` CallLLM error branch — provider-side safety transport
   errors: finalizes normally with the exact line so the refusal persists
   in session history instead of surfacing as a technical error.

Transport-level blocks that never reach the turn (network failures
before a response exists) stay technical errors.

## Prompt Workshop (`pkg/promptwork`)

Deterministic, vendor-neutral building blocks — pure functions, no model,
no I/O:

- `Brief` / `Build` / `Validate`: portable Markdown brief renderer.
  Empty sections are omitted; short briefs stay short.
- `Review`: rule-based lint for hedge words, structural gaps (missing
  objective/acceptance), vendor references, and secrets. Shallow by
  design: it flags what is mechanically checkable, never intent.

## Token economics

Measured by `TestHal9001PromptOverheadModest` (stage 1) and
`TestHalContextCostBreakdown` (stage 2, realistic request: 10-turn history
+ retrieved context + full tool profile). Token counts use the repo's own
`pkg/tokenizer` estimator unless noted.

| Component | Tokens (est.) |
|---|---|
| HAL identity + personality (static) | ~800 |
| Provider tool definitions (6-tool chat profile) | ~865 |
| **Instruction foundation (static + defs)** | **~1,666** |
| 10-turn conversation history + live question | ~3,325 |
| MPM retrieved block (40 facts) | included above |
| **Total representative request** | **~5,057** |

The 10,000-token figure is a soft design budget for the instruction
foundation, not a quota or a ceiling on useful context: the foundation
uses ~17% of it, leaving headroom for history and retrieval. Tool schemas
— not persona prose — dominate the foundation, which is why the 6-tool
chat profile is the main lever. The static foundation is byte-stable
across builds (asserted), keeping provider-side prefix caches hot;
per-request dynamic context (date, session) is never folded into it.
